# Chapter 15. 파일 시스템

우리가 일상적으로 사용하는 **파일**과 **디렉터리**는 운영체제 내부의 **파일 시스템**이라는 프로그램이 관리하는 대상이다. 데이터 관점에서 파일과 디렉터리는 보조기억장치에 저장된 데이터 덩어리일 뿐이며, 파일 시스템이 이를 일목요연하게 저장·관리한다.

## 15-1 파일과 디렉터리

### 파일

**파일(file)** 은 보조기억장치에 저장된 의미 있는 정보들을 모은 논리적 단위다. 파일은 파일을 구성하는 정보와, 그 파일을 설명하는 **부가 정보(속성, 메타데이터)** 로 이루어진다.

**파일 속성의 예**

| 속성 | 설명 |
| --- | --- |
| **유형(type)** | 운영체제가 인식하는 파일의 종류. **확장자**로 힌트를 준다 (예: `.exe` 실행 파일) |
| 크기 | 파일의 현재 크기와 최대 크기 |
| 위치 | 보조기억장치 내 파일의 위치 |
| 생성/수정/접근 날짜 | 만들어진·마지막으로 수정한·접근한 시각 |
| 생성자·소유자 | 파일을 만들거나 소유한 사용자 |

> 파일을 다루는 모든 작업은 운영체제를 통해 이루어진다. 응용 프로그램은 파일에 직접 접근할 수 없고, **시스템 호출**로 운영체제에 요청해야 한다. (운영체제는 파일 생성·삭제·열기·닫기·읽기·쓰기 등의 파일 연산용 시스템 호출을 제공한다.)

### 디렉터리

**디렉터리(directory)** 는 윈도우에서 **폴더**라고도 부른다.

- **1단계 디렉터리** — 옛날 방식으로, 하나의 디렉터리 아래에 모든 파일이 존재하는 구조.
- **트리 구조 디렉터리** — 오늘날의 방식으로, 디렉터리 안에 서브 디렉터리를 두어 여러 계층으로 관리한다. 최상단의 디렉터리를 **루트 디렉터리(root directory)** 라 하며, 리눅스·유닉스에서는 `/`로 표현한다.

> 많은 운영체제는 **디렉터리를 특별한 형태의 파일로 간주**한다. 파일 내부에 파일 정보가 담기듯, 디렉터리 내부에는 그 디렉터리에 담긴 대상(파일·하위 디렉터리)들의 정보가 담긴다. 이 정보는 보통 **테이블(표)** 형태로 저장되며, 각 행을 **디렉터리 엔트리(directory entry)** 라 한다.

**디렉터리 엔트리** 에는 공통적으로 담긴 대상의 **이름**과 그 대상의 **위치를 유추할 수 있는 정보**가 저장된다. (파일 시스템에 따라 파일 속성까지 담기기도 한다.)

### 경로

디렉터리를 계층적으로 관리하면서 생겨난 개념이 **경로(path)** 다. 경로는 디렉터리를 이용해 파일·디렉터리의 위치와 이름을 특정하는 정보다.

- 같은 디렉터리에는 같은 이름의 파일이 존재할 수 없지만, **경로가 다르면** 같은 이름의 파일이 존재할 수 있다.

| 경로 | 설명 |
| --- | --- |
| **절대 경로(absolute path)** | **루트 디렉터리**에서부터 자기 자신까지 이르는 고유한 경로 (예: `/home/민철/a.sh`) |
| **상대 경로(relative path)** | **현재 디렉터리**에서부터 자기 자신까지 이르는 경로 |

> `/`는 루트 디렉터리를 나타내는 동시에 디렉터리 사이의 **구분자**로도 쓰인다. 또한 `..`은 **상위 디렉터리**, `.`은 **현재 디렉터리**를 가리킨다. (디렉터리 엔트리에도 `.`과 `..`이 위치 정보와 함께 저장되어, 상위 디렉터리로 거슬러 올라갈 수 있다.)

## 15-2 파일 시스템

**파일 시스템(file system)** 은 파일과 디렉터리를 보조기억장치에 일목요연하게 저장하고 접근할 수 있도록 하는 운영체제 내부 프로그램이다. 하나의 컴퓨터에서 여러 파일 시스템을 사용할 수 있다.

### 파티셔닝과 포매팅

새 하드디스크·SSD에는 곧바로 파일을 저장할 수 없다. 먼저 **파티셔닝**과 **포매팅**을 거쳐야 한다.

| 작업 | 설명 |
| --- | --- |
| **파티셔닝(partitioning)** | 저장장치의 논리적 영역을 구획하는 작업. (서랍에 칸막이를 치는 것에 비유) 나누어진 영역 하나하나를 **파티션**이라 한다 |
| **포매팅(formatting)** | 파일 시스템을 설정해 어떤 방식으로 파일을 저장·관리할지 결정하고, 새 데이터를 쓸 준비를 하는 작업. 이때 **파일 시스템이 결정**된다 |

> 포매팅에는 공장에서 수행되는 **저수준 포매팅**과 파일 시스템을 만드는 **논리적 포매팅**이 있는데, 보통 접하는 포매팅은 논리적 포매팅이다. 파티션마다 서로 다른 파일 시스템을 설정할 수 있다.

### 파일 할당 방식

파일과 디렉터리는 하드디스크에 **블록(block)** 단위로 읽고 써진다. (하드디스크의 가장 작은 저장 단위인 섹터는 너무 많고 작아, 하나 이상의 섹터를 블록으로 묶어 관리한다.) 하나의 파일은 여러 블록에 걸쳐 저장되며, 할당 방식은 크게 두 가지다.

#### 연속 할당

파일을 **연속된 블록**에 저장하는 가장 단순한 방식이다. 디렉터리 엔트리에 **첫 번째 블록 주소**와 **블록 단위 길이**만 있으면 파일 위치를 알 수 있다.

- **단점** — **외부 단편화**를 일으킨다. (파일이 삭제되며 생긴 빈 블록들이 흩어져, 총량은 충분해도 연속 공간이 없어 큰 파일을 할당하지 못함) → 오늘날 잘 쓰이지 않는다.

#### 불연속 할당 — 연결 할당

파일을 여러 블록에 **흩어서** 저장하되, 각 블록의 일부에 **다음 블록의 주소**를 저장해 블록들이 사슬처럼 이어지는 방식이다. (연결 리스트 구조) 파일의 마지막 블록에는 끝을 나타내는 표시자(예: `-1`)를 기록한다.

- **단점 1** — 반드시 첫 번째 블록부터 순차적으로 읽어야 해, **임의 위치 접근 속도가 느리다**.
- **단점 2** — 한 블록이 고장 나면 그 **이후 블록에 모두 접근할 수 없다**.

#### 불연속 할당 — 색인 할당

파일의 **모든 블록 주소를 하나의 색인 블록(index block)** 에 모아 관리하는 방식이다. 색인 블록만 읽으면 파일의 모든 블록 위치를 알 수 있어, 연결 할당보다 **임의 접근이 용이**하다. 디렉터리 엔트리에는 파일 이름과 **색인 블록 주소**가 기록된다.

### 파일 시스템 구조

앞의 이론을 기반으로 만들어진 대표적인 파일 시스템 두 가지를 살펴본다.

#### FAT 파일 시스템 (연결 할당 기반)

**FAT** 파일 시스템은 연결 할당의 단점을 보완한 것으로, USB·SD 카드 등 저용량 저장장치에 오늘날까지 많이 쓰인다.

- 연결 할당은 각 블록 안에 다음 블록 주소를 흩어 저장해 문제가 생겼다. FAT는 이 **다음 블록 주소들을 한데 모아 테이블**로 관리하는데, 이 테이블이 **FAT(File Allocation Table)** 다.
- FAT를 **메모리에 캐시**하면 다음 블록을 찾으려고 매번 보조기억장치를 뒤질 필요가 없어, 임의 접근 속도도 개선된다.
- 버전에 따라 FAT12/FAT16/FAT32로 나뉜다. (숫자는 블록을 표현하는 비트 수) 디렉터리 엔트리에 파일 **속성**까지 명시한다.

#### 유닉스 파일 시스템 (색인 할당 기반)

유닉스 파일 시스템은 색인 블록을 **아이노드(i-node)** 라 부른다. 아이노드는 파일의 **속성 정보**와 **15개의 블록 주소**를 저장한다. 파일마다 고유한 아이노드가 있어, 아이노드만 읽으면 파일의 속성과 위치를 모두 알 수 있다. (디렉터리 엔트리는 **파일 이름 + 아이노드 번호** 만으로 구성 가능하다.)

**15개보다 많은 블록이 필요한 큰 파일**은 다음과 같이 처리한다.

| 블록 주소 | 용도 |
| --- | --- |
| 1~12번 (12개) | **직접 블록** — 데이터가 저장된 블록의 주소를 직접 저장 |
| 13번 | **단일 간접 블록** — 데이터 블록 주소를 저장한 블록의 주소 |
| 14번 | **이중 간접 블록** — 단일 간접 블록들의 주소를 저장한 블록의 주소 |
| 15번 | **삼중 간접 블록** — 이중 간접 블록들의 주소를 저장한 블록의 주소 |

> 이 방식으로 아이노드 하나만으로 아무리 큰 파일이라도 속성과 위치를 모두 표현할 수 있다. (삼중 간접 블록까지 쓰면 웬만한 크기의 파일은 전부 저장 가능하다.)

<img width="1448" height="1086" alt="image" src="https://github.com/user-attachments/assets/589d0b2a-c7ca-4d0b-98c7-35dce8ec8c5c" />

> **참고 — 그 외 파일 시스템** — 윈도우의 **NTFS**, 리눅스의 **ext4** 등도 널리 쓰인다. 위 개념을 이해하면 다른 파일 시스템도 어렵지 않게 이해할 수 있다.

### 저널링

> **참고** — 이 항목은 강의 범위 밖의 보충 내용이다. **저널링(journaling)** 은 파일 시스템의 안정성을 높이는 기법이다. 파일을 실제로 변경하기 전에, 수행할 작업 내역을 **저널(로그) 영역**에 먼저 기록해 둔다. 작업 도중 갑자기 전원이 꺼지는 등 문제가 생겨도, 재부팅 시 저널을 확인해 중단된 작업을 복구하거나 되돌릴 수 있어 파일 시스템 손상을 막는다. (ext4, NTFS 등이 저널링을 지원한다.)

### 마운트

> **참고** — 이 항목은 강의 범위 밖의 보충 내용이다. **마운트(mount)** 는 한 저장장치의 파일 시스템을 다른 파일 시스템의 특정 디렉터리에 연결해, 하나의 디렉터리 트리에서 함께 접근할 수 있게 하는 작업이다. 예를 들어 USB를 꽂으면 그 파일 시스템이 기존 디렉터리 구조의 한 지점(마운트 지점)에 연결되어, 평소 파일에 접근하듯 USB의 파일에도 접근할 수 있게 된다.
