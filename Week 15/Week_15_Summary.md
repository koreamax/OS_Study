# 교착 상태 해결 방법 & 연속 메모리 할당

## 13-2 교착 상태 해결 방법

교착 상태를 해결하는 방법은 크게 **예방, 회피, 검출 및 회복** 세 가지로 나뉜다.

### 교착 상태 예방

교착 상태 발생의 **네 가지 조건(상호 배제·점유와 대기·비선점·원형 대기) 중 하나를 원천적으로 없애는** 방법이다. 애초에 조건이 충족되지 않으면 교착 상태도 발생하지 않는다.

| 없애는 조건 | 방법 | 문제점 |
| --- | --- | --- |
| **상호 배제 제거** | 모든 자원을 공유 가능하게 함 | 현실적으로 모든 자원을 공유할 수는 없음 |
| **점유와 대기 제거** | 특정 프로세스에 자원을 모두 할당하거나 아예 할당하지 않음(전부 아니면 전무) | 자원 활용률이 낮아지고, 많은 자원을 요구하는 프로세스가 불리해져 **기아 현상** 우려 |
| **비선점 제거** | 자원을 뺏을 수 있게 함 | 뺏어도 되는 일부 자원(CPU 등)에만 적용 가능. 모든 자원에 적용 불가 |
| **원형 대기 제거** | 모든 자원에 번호를 붙이고 **오름차순으로만** 할당 | 수많은 자원에 번호를 붙이기 어렵고, 번호 부여 방식에 따라 자원 활용률이 달라짐 |

> 예방은 확실하지만 여러 부작용(자원 활용률 저하 등)을 낳는다.

### 교착 상태 회피

교착 상태를 **무리한 자원 할당의 결과**로 보고, 교착 상태가 발생하지 않을 만큼만 조심스럽게 자원을 할당하는 방법이다.

| 용어 | 의미 |
| --- | --- |
| **안전 상태** | 모든 프로세스가 정상적으로 자원을 할당받고 종료될 수 있는 상태 |
| **불안전 상태** | 교착 상태가 발생할 수도 있는 상태 |
| **안전 순서열** | 교착 상태 없이 모든 프로세스가 자원을 할당받고 실행을 마칠 수 있는 순서 |

- 안전 순서열이 **존재하면** 안전 상태, **없으면** 불안전 상태다.
- 교착 상태 회피는 항상 **안전 상태를 유지하도록** 자원을 할당하는 방식이다. (대표적으로 은행원 알고리즘)

### 교착 상태 검출 및 회복

교착 상태 발생을 **미리 막지 않고**, 발생하면 그때 회복하는 방법이다. 운영체제는 프로세스가 자원을 요구할 때마다 할당하며 교착 상태 발생 여부를 주기적으로 검사하고, 교착 상태가 검출되면 다음 방법으로 회복한다.

| 회복 방법 | 설명 |
| --- | --- |
| **선점을 통한 회복** | 교착 상태가 해결될 때까지 한 프로세스씩 자원을 강제로 뺏어 다른 프로세스에 몰아줌 |
| **프로세스 강제 종료를 통한 회복** | 교착 상태에 놓인 프로세스를 모두 강제 종료하거나, 교착 상태가 풀릴 때까지 하나씩 강제 종료 (가장 단순하고 확실하지만 작업 내용을 잃을 수 있음) |

> **타조 알고리즘(ostrich algorithm)** — 교착 상태를 무시하고 아무 조치도 하지 않는 방법. (모래에 머리를 파묻는 타조에 비유) 교착 상태가 매우 드물게 발생한다면, 이를 감지·회복하는 비용이 더 클 수 있으므로 차라리 무시하는 것이 나을 수 있다는 관점이다.

## Chapter 14. 가상 메모리

## 14-1 연속 메모리 할당

프로세스에 **연속적인 메모리 공간을 할당**하는 방식을 연속 메모리 할당이라 한다. 이를 다루기 위해 먼저 스와핑, 메모리 할당 방식, 그리고 그 한계인 외부 단편화를 살펴본다.

### 스와핑

메모리에 적재된 프로세스 중에는 오랫동안 사용되지 않는 것들도 있다. **스와핑(swapping)**은 이런 프로세스를 임시로 보조기억장치로 내보내고, 그 빈 공간에 다른 프로세스를 적재하는 기법이다.

| 용어 | 의미 |
| --- | --- |
| **스왑 영역(swap space)** | 프로세스를 임시로 대피시키는 보조기억장치의 일부 영역 |
| **스왑 아웃(swap-out)** | 현재 실행되지 않는 프로세스를 메모리에서 스왑 영역으로 내보내는 것 |
| **스왑 인(swap-in)** | 스왑 영역의 프로세스를 다시 메모리로 들여오는 것 (스왑 아웃되기 전과 **다른 주소**에 적재될 수 있음) |

> 스와핑을 이용하면 프로세스들이 요구하는 메모리 크기의 합이 실제 물리 메모리 크기보다 커도 프로세스들을 동시에 실행할 수 있다. (`free`, `top` 등의 명령어로 스왑 영역 크기를 확인할 수 있다.)

### 메모리 할당

프로세스는 비어 있는 메모리 공간에 연속적으로 할당된다. 빈 공간이 여러 개일 때 어디에 할당할지 결정하는 방식은 세 가지다.

| 방식 | 설명 | 특징 |
| --- | --- | --- |
| **최초 적합(first fit)** | 위에서부터 훑어보다 **처음 발견한** 충분한 공간에 할당 | 검색이 빨라 빠른 할당 가능 |
| **최적 적합(best fit)** | 빈 공간을 모두 탐색해 프로세스가 들어갈 수 있는 **가장 작은** 공간에 할당 | 공간 낭비가 적어 보이지만 탐색 시간이 김 |
| **최악 적합(worst fit)** | 빈 공간을 모두 탐색해 **가장 큰** 공간에 할당 | 할당 후 남는 공간이 커서 다른 프로세스를 넣기 유리 |

### 외부 단편화

연속 메모리 할당은 **외부 단편화(external fragmentation)**라는 근본적 문제를 낳는다.

- 프로세스들이 실행되고 종료되기를 반복하면, 프로세스 사이사이에 **작은 빈 공간들**이 생긴다.
- 이 빈 공간들은 각각으로는 너무 작아 새 프로세스를 할당하기 어렵다. 이렇게 **총량은 충분하지만 흩어져 있어 사용하지 못하는** 낭비 공간이 발생하는 현상이 외부 단편화다.

> 예) 빈 공간이 여기저기 50MB씩 흩어져 총 200MB가 남아도, 연속된 100MB가 없으면 100MB 프로세스를 적재할 수 없다.

**외부 단편화 완화 방법**

- **압축(compaction, 메모리 조각 모음)** — 흩어진 빈 공간들을 하나로 모으는 방법. 여기저기 흩어진 프로세스를 한쪽으로 밀어 옮겨 빈 공간을 모은다. 단, 프로세스를 재배치하는 동안 시스템이 하던 일을 중지해야 하고 오버헤드가 크다.
- 근본적인 해결책으로 등장한 것이 다음 절의 **가상 메모리(페이징)** 기법이다.
