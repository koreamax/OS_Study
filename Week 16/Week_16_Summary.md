# 페이징 & 페이지 교체

## 14-2 페이징

연속 메모리 할당의 외부 단편화 문제를 해결하고, 물리 메모리보다 큰 프로세스도 실행할 수 있게 하는 **가상 메모리** 관리 기법이다. 가상 메모리 기법에는 페이징과 세그멘테이션이 있으며, 여기서는 오늘날 대부분의 운영체제가 사용하는 **페이징**을 다룬다.

### 페이징이란

외부 단편화가 생기는 근본 원인은 프로세스를 **연속적인** 공간에 통째로 할당하기 때문이다. 페이징은 이를 **잘게 나누어** 불연속적으로 할당한다.

| 용어 | 의미 |
| --- | --- |
| **페이지(page)** | 프로세스의 논리 주소 공간을 일정한 크기로 자른 단위 |
| **프레임(frame)** | 메모리(물리 주소 공간)를 페이지와 **동일한 크기**로 자른 단위 |

**페이징(paging)** — 프로세스를 페이지 단위로 자르고, 메모리를 프레임 단위로 잘라, 페이지를 프레임에 할당하는 방식이다. 페이지와 프레임 크기가 같으므로 어떤 페이지든 어떤 프레임에나 들어갈 수 있고, 프로세스가 **연속되지 않은 프레임에 흩어져** 저장돼도 문제없다. → 외부 단편화 해결.

> **페이징에서의 스와핑** — 페이징을 쓰는 시스템에서는 프로세스 전체가 아니라 **페이지 단위로** 스왑 인/스왑 아웃된다. 이를 각각 **페이지 인(page-in)**, **페이지 아웃(page-out)**이라 한다. 덕분에 프로세스 전체를 메모리에 올리지 않고, 실행에 필요한 페이지만 메모리에 두고 당장 필요 없는 페이지는 스왑 영역에 둘 수 있다. → 물리 메모리보다 큰 프로세스 실행 가능.

### 페이지 테이블

페이지가 프레임에 불연속적으로 흩어져 할당되면, CPU 입장에서는 다음에 실행할 페이지가 어느 프레임에 있는지 순차적으로 알기 어렵다. 이를 해결하는 것이 **페이지 테이블(page table)**이다.

- 페이지 테이블은 **페이지 번호 → 프레임 번호**의 대응 정보를 담은 표다.
- 물리적으로 흩어진 페이지라도, CPU는 페이지 테이블을 통해 **논리적으로는 연속적으로** 인식할 수 있다.
- 프로세스마다 각자의 페이지 테이블을 가진다.

> **내부 단편화(internal fragmentation)** — 페이징의 부작용. 프로세스 크기가 페이지 크기의 배수가 아니면 마지막 페이지에 빈 공간이 생긴다. (예: 페이지 크기 10KB, 프로세스 108KB → 마지막 페이지에 2KB 낭비) 다만 내부 단편화는 페이지 하나 크기 미만이라, 외부 단편화보다 손실이 작다. 페이지 크기를 무작정 키우면 내부 단편화가 커지므로 적절한 크기 설정이 중요하다.

> **페이지 테이블 베이스 레지스터(PTBR)** — 각 프로세스의 페이지 테이블이 저장된 **메모리상 주소**를 가리키는 레지스터다. 페이지 테이블은 메모리(커널 영역)에 저장되고, PTBR가 그 위치를 가리킨다. (문맥 교환 시 PTBR 값도 함께 바뀐다.)

> **TLB(Translation Lookaside Buffer)** — 페이지 테이블이 메모리에 있으면 메모리에 두 번(페이지 테이블 접근 + 실제 프레임 접근) 접근해야 해 느리다. 이를 완화하려고, 참조 지역성에 따라 최근 참조한 페이지 테이블 일부를 담아두는 **캐시 메모리**가 TLB다. TLB 히트면 메모리 접근 한 번을 아낄 수 있다.

### 주소 변환

페이징 시스템에서 하나의 논리 주소는 **페이지 번호(page number)**와 **변위(offset)**로 이루어진다.

```
논리 주소 = <페이지 번호, 변위>
```

변환 과정:
1. **페이지 번호**로 페이지 테이블을 참조해, 그 페이지가 담긴 **프레임 번호**를 알아낸다.
2. 알아낸 프레임의 시작 주소에 **변위**를 더해 실제 물리 주소를 구한다.

> **변위(offset)**는 페이지(프레임) 내에서 얼마나 떨어져 있는지를 나타낸다. 페이지와 프레임 크기가 같으므로, 페이지 안에서의 변위와 프레임 안에서의 변위는 동일하다. 따라서 페이지 번호만 프레임 번호로 바꾸면 되고 변위는 그대로 쓴다.

### 페이지 테이블 엔트리 (PTE)

페이지 테이블의 각 행을 **페이지 테이블 엔트리(PTE)**라 한다. 엔트리에는 페이지 번호·프레임 번호 외에도 여러 정보가 담긴다.

| 비트 | 의미 |
| --- | --- |
| **유효 비트(valid bit)** | 해당 페이지가 현재 **메모리에 적재되어 있는지** 여부. 0이면 스왑 영역에 있음(접근 시 페이지 폴트 발생) |
| **보호 비트(protection bit)** | 페이지에 대한 접근 권한(읽기/쓰기/실행). 예: 읽기 전용 페이지에 쓰기를 막음 |
| **참조 비트(reference bit)** | CPU가 이 페이지에 **접근한 적 있는지** 여부 |
| **수정 비트(modified bit / dirty bit)** | 이 페이지에 데이터를 **쓴(변경한) 적 있는지** 여부 |

> **수정 비트(더티 비트)의 용도** — 페이지가 메모리에서 스왑 영역으로 쫓겨날 때, 수정된 적이 없으면(수정 비트 0) 스왑 영역의 기존 내용과 같으므로 그냥 덮어쓰면 되지만, 수정된 적이 있으면(수정 비트 1) 변경 내용을 스왑 영역에 **다시 기록**해야 한다. 불필요한 쓰기 작업을 줄이기 위한 비트다.

## 14-3 페이지 교체

프로세스를 실행하려면 관련된 모든 페이지를 메모리에 올려야 할 것 같지만, 실제로는 그렇지 않다. 필요한 페이지만 적재하는 **요구 페이징**과, 메모리가 가득 찼을 때 어떤 페이지를 내보낼지 정하는 **페이지 교체**를 다룬다.

### 요구 페이징

**요구 페이징(demand paging)** — 프로세스의 모든 페이지를 처음부터 올리지 않고, 실행에 필요한 페이지가 **요구될 때(요청될 때) 메모리에 적재**하는 기법이다.

동작 흐름:
1. CPU가 특정 페이지에 접근하는 명령어를 실행한다.
2. 그 페이지가 메모리에 있으면(유효 비트 1) 그대로 접근한다.
3. 없으면(유효 비트 0) **페이지 폴트(page fault)**가 발생한다.
4. 페이지 폴트를 처리(스왑 영역의 페이지를 메모리로 적재)한 뒤, 유효 비트를 1로 바꾸고 접근한다.

> **페이지 폴트(page fault)** — 접근하려는 페이지가 메모리에 없어 발생하는 예외(인터럽트). 발생 시 CPU는 기존 작업을 백업하고, 페이지 폴트 처리 루틴을 실행해 원하는 페이지를 메모리로 가져온 뒤 실행을 재개한다.

> **순수 요구 페이징(pure demand paging)** — 아무 페이지도 적재하지 않은 채 실행을 시작해, 첫 명령어부터 페이지 폴트를 계속 일으키며 필요한 페이지를 점차 적재하는 방식.

### 페이지 교체 알고리즘

요구 페이징으로 페이지를 계속 적재하다 보면 메모리가 가득 찬다. 이때 **어떤 페이지를 내보낼지(page-out)** 결정하는 것이 페이지 교체 알고리즘이다. **페이지 폴트를 적게 일으키는** 알고리즘이 좋은 알고리즘이다.

> **페이지 폴트 횟수** 측정을 위해 CPU가 참조하는 페이지들을 나열한 **페이지 참조열(page reference string)**을 사용한다. (연속된 중복 페이지는 페이지 폴트를 일으키지 않으므로 제외하고 나열한다.)

| 알고리즘 | 기준 | 특징 |
| --- | --- | --- |
| **FIFO 페이지 교체** | 메모리에 가장 **먼저 올라온** 페이지부터 교체 | 단순하나, 자주 쓰이는 페이지도 오래됐다는 이유로 내보낼 수 있음 |
| **최적 페이지 교체(OPT)** | **앞으로 가장 오래 사용되지 않을** 페이지를 교체 | 페이지 폴트가 가장 적음(이론상 최선). 단, 미래 참조를 알아야 해 **실제 구현 불가**. 주로 다른 알고리즘의 성능 평가 하한선(기준)으로 사용 |
| **LRU 페이지 교체** | **가장 오래 전에 참조된**(최근에 안 쓰인) 페이지를 교체 | 최적에 가깝게 동작. 참조 시각을 기록해야 함 |

> **2차 기회(second chance) FIFO** — FIFO를 개선해, 내보낼 차례가 된 페이지의 참조 비트가 1이면 한 번 더 기회를 주고(참조 비트를 0으로) 큐 뒤로 보내는 방식.

### 스래싱과 프레임 할당

**스래싱(thrashing)** — 프로세스가 실제 실행보다 **페이지 교체(스왑 인/아웃)에 더 많은 시간을 쓰는** 상태. 페이지 폴트가 지나치게 자주 발생해 CPU 이용률이 오히려 떨어진다.

> **원인** — 동시에 실행되는 프로세스 수가 늘면 각 프로세스에 돌아가는 프레임이 부족해지고, 페이지 폴트가 빈번해진다. 어느 시점(임계점)을 넘으면 프로세스 수가 늘수록 CPU 이용률이 급격히 떨어진다. → 스래싱은 프로세스 수보다 **각 프로세스에 프레임을 충분히 할당하지 못한 것**이 근본 원인이다.

<img width="1536" height="1024" alt="image" src="https://github.com/user-attachments/assets/ab9cf614-518b-4948-a412-736d1a0c6183" />

**프레임 할당 방식** — 스래싱을 막으려면 각 프로세스에 적절한 수의 프레임을 할당해야 한다.

| 구분 | 방식 | 설명 |
| --- | --- | --- |
| **정적 할당** | 균등 할당 | 모든 프로세스에 프레임을 **균등하게** 나눠줌 |
| | 비례 할당 | 프로세스 **크기에 비례**해 프레임을 나눠줌 |
| **동적 할당** | 작업 집합 모델 | 실행 중 **자주 참조하는 페이지 집합(작업 집합)**을 파악해, 그만큼의 프레임을 할당 |
| | 페이지 폴트 빈도 | 페이지 폴트율의 상한·하한을 정해, 상한보다 높으면 프레임을 늘리고 하한보다 낮으면 줄임 |

> 정적 할당은 프로세스 실행 과정을 고려하지 않고 크기·개수만으로 나누는 반면, 동적 할당은 실행 중 프로세스의 실제 페이지 사용 양상을 반영한다.
